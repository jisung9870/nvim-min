# 릴리스 관리

## 정책 상태

상태: 채택. nvim-min은 Git 태그와 `CHANGELOG.md`를 기준으로 릴리스를 관리한다. 현재 태그가
없으므로 첫 릴리스 전까지 모든 사용자 영향 변경은 `Unreleased`에 기록한다.

## 버전 규칙

태그와 문서 버전은 `vMAJOR.MINOR.PATCH` 형식을 사용한다.

| 변경 | 버전 | 예시 |
|---|---|---|
| 기존 키·명령·설치 계약을 깨는 변경 | MAJOR | 기본 leader 변경, 지원 Neovim 버전의 비호환 상승 |
| 하위 호환 기능 추가 | MINOR | 새 언어, 플러그인, 사용자 명령 추가 |
| 하위 호환 수정·문서 보완·잠금 업데이트 | PATCH | 오류 수정, 문서 정정, 호환 가능한 플러그인 갱신 |

첫 안정 릴리스 전 `0.y.z`를 사용한다면 호환성을 깨는 변경은 MINOR를 올리고, 하위 호환 수정은
PATCH를 올린다. `1.0.0` 이후에는 위 표를 그대로 적용한다.

## Changelog 작성 규칙

변경은 PR 작성 시 `CHANGELOG.md`의 `Unreleased` 아래에 추가한다.

| 분류 | 기록 대상 |
|---|---|
| Added | 사용자에게 보이는 새 기능·언어·명령·문서 |
| Changed | 기존 동작이나 기본값 변경 |
| Deprecated | 제거 예정 기능과 대체 경로 |
| Removed | 삭제된 기능·지원 환경 |
| Fixed | 사용자 증상이 있었던 수정 |
| Security | 보안 취약점 또는 노출 축소 |

내부 리팩터링처럼 사용자 영향이 전혀 없는 변경은 생략할 수 있다. 한 항목에는 무엇이
달라졌는지와 사용자가 해야 할 조치를 함께 적고, 커밋 메시지를 그대로 복사하지 않는다.

예시:

```md
### Changed

- Neovim 최소 버전을 0.12로 올렸다. 업그레이드 전 `nvim --version`을 확인해야 한다.
```

## 릴리스 전 검증

릴리스 담당자는 같은 잠금 파일을 사용한 깨끗한 환경에서 다음 수용 기준을 확인한다.

| 영역 | 확인 방법 | 수용 기준 |
|---|---|---|
| 시작 | `nvim` | Lua 오류 없이 편집 화면 진입 |
| 플러그인 | `:PackStatus` | 선언과 잠금 파일이 일치 |
| 상태 | `:checkhealth` | 신규 필수 오류 없음 |
| 파서 | `:TSSync` 후 대표 파일 열기 | 설치 완료, 하이라이트 동작 |
| LSP | 대표 YAML/Python/Terraform/Go/Markdown | 기대 서버 연결, 진단/이동 동작 |
| 편집 | 저장과 `<leader>cf` | 기대 포매터 실행, Markdown은 보존 |
| 탐색 | 파일 picker와 grep | 결과 표시, 제외 정책 유지 |
| Git | hunk와 Diffview | Git 저장소에서 정상 동작 |
| 터미널 | toggleterm 열기/닫기 | Normal/Terminal 전환과 tmux 이동 정상 |
| 문서 | Markdown 링크·제목 검사 | 끊어진 내부 링크 없음 |

실행하지 못한 항목은 통과로 간주하지 않는다. 차단 원인과 영향 범위를 릴리스 이슈에 기록하고
해결하거나 릴리스를 연기한다.

## 릴리스 절차

예시 버전을 `0.1.0`으로 표시한다. 실제 버전은 변경 범위에 맞게 결정한다.

1. 작업 트리와 기준 브랜치를 확인한다.

   ```sh
   git status --short
   git branch --show-current
   ```

2. `CHANGELOG.md`의 `Unreleased` 내용을 `0.1.0 - YYYY-MM-DD` 섹션으로 옮긴다.
3. 비어 있는 새 `Unreleased` 섹션을 최상단에 만든다.
4. 비교 링크를 이전 태그와 새 태그에 맞게 갱신한다.
5. 위 검증표를 수행하고 결과를 릴리스 PR에 기록한다.
6. 릴리스 커밋을 만든다.

   ```sh
   git add CHANGELOG.md docs
   git commit -m "Release v0.1.0"
   ```

7. 검증된 커밋에 annotated tag를 만든다.

   ```sh
   git tag -a v0.1.0 -m "nvim-min v0.1.0"
   git show --stat v0.1.0
   ```

8. 원격 반영 권한과 대상을 다시 확인한 뒤 브랜치와 태그를 푸시한다.

   ```sh
   git push origin HEAD
   git push origin v0.1.0
   ```

원격 push와 릴리스 게시물 생성은 외부 변경이므로 담당자가 대상 저장소와 권한을 확인한 뒤
수행한다.

## 릴리스 노트

릴리스 노트는 changelog를 반복하기보다 다음 순서로 작성한다.

1. 한 문단 요약
2. 주요 사용자 변화
3. 호환성 또는 마이그레이션 조치
4. 알려진 제한
5. 이전 태그와의 비교 링크

플러그인 리비전 전체 목록은 `nvim-pack-lock.json`이 담당한다. 릴리스 노트에는 사용자가 체감할
변경과 문제 해결에 필요한 리비전만 적는다.

## 실패와 롤백

태그 전 검증 실패는 수정 후 절차를 다시 시작한다. 태그를 만들었지만 아직 push하지 않았다면
잘못된 로컬 태그를 삭제하고 수정된 커밋에 다시 만든다.

```sh
git tag -d v0.1.0
```

이미 공유한 태그는 같은 이름으로 덮어쓰지 않는다. 문제를 수정한 새 PATCH 버전을 발행하고,
긴급한 경우 사용자에게 마지막 정상 태그로 체크아웃하도록 안내한다.

```sh
git switch --detach v0.1.0
```

설정 전체를 되돌리지 않아도 되는 플러그인 회귀는
[잠금 파일 롤백](operations.md#잠금-파일-롤백)을 사용할 수 있다.

## 릴리스 완료 기준

- [ ] 버전이 변경 범위와 일치한다.
- [ ] `Unreleased` 변경이 날짜가 있는 버전 섹션으로 이동했다.
- [ ] 릴리스 검증표가 모두 통과했다.
- [ ] 설정, 잠금 파일, 문서가 같은 커밋을 설명한다.
- [ ] annotated tag가 검증된 커밋을 가리킨다.
- [ ] 릴리스 노트에 마이그레이션과 알려진 제한이 있다.
